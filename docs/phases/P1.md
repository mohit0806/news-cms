# P1 — Foundation and Admin Shell: Implementation Plan

**Status:** Planned (not executed). **Phase:** P1 of `docs/MASTER_PLAYBOOK.md` (Phase index §4, tasks §6).
**Canonical path:** `docs/phases/P1.md` (this file). No competing P1 plan.
**Mode note:** plan authoring only — no P1 implementation in this pass.

## 1. Header, objective, scope, exclusions

**Objective:** deliver the secure, reusable administrative foundation later NewsCMS features build on:
identity/access enforcement, hardened auth + sessions, typed settings + initial UI, immutable audit + viewer,
revision/concurrency primitives, reusable admin UI patterns, locale/time plumbing, notifications, and the
minimum coherent admin shell to use them — with tests, docs, and evidence for the P1 gate.

P1 provides a secure foundation, **not** a finished editorial CMS and **not** production readiness
(P5 owns production readiness; see §17).

**In scope:** PRD §4, §6.1.4 (primitives only), §8.1 (plumbing only), §15 (exc. homepage blocks admin),
§16, §21.3 (minimal status page); TRD §6.4–§6.5, §7, §11 (part); ARCH §§3/5/6/8; ADR-0001…0004 (install phases);
`design.md` §§B–G/I–J (admin application only).

**Explicit exclusions (stay in their phases):** article create/edit/review/schedule/publish workflows (P2);
categories/tags/authors management (P2); full media-library UI (P2-T05; P1 builds only the picker *boundary*);
block-editor implementation + body schema (P2-T04); pages/menus/homepage/public themes/RSS/SEO rendering (P3);
search, analytics products, ads management, optional modules (P2–P4); any generic admin framework, custom
kernel/DI/event-bus/module-registry, package-per-capability, Filament or Livewire/Blade/Flux replacement.

Where later features need a P1 primitive, build and test **the primitive only**.

## 8. Permission matrix design (from PRD §4.2)

Catalog = the 29 PRD §4.2 keys verbatim (count verified by test); seeded defaults per the matrix. P1 enforces the subset touching P1
surfaces: `users.manage`, `roles.manage`, `settings.manage`, `audit.view`, `system.view` (+ `articles.*` etc.

**P2 registration contract:** a new resource (a) adds its keys to `Permissions::keys()` (code-owned, versioned),
(b) adds seeded defaults to `Permissions::defaults()`, (c) protects routes/actions/policies with those keys
(server-side; UI gating is never sufficient), (d) extends the generated matrix test — the matrix fails CI for
any guarded action missing coverage. Never invent privileges outside PRD §4.2 without an owner decision.

but the P1 brief asserts Reporter excludes category/tag creation. Narrow blast radius: Q-P1-01 affects ONLY the

Reporter-minus-category/tag-creation per Q3 either way. No invented privileges.
