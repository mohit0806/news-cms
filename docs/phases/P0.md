**Status:** Planned (not executed). **Phase:** P0 of `docs/MASTER_PLAYBOOK.md`.

## 1. Objective and scope boundary

P0 establishes a reproducible development setup, verified toolchain, CI and quality gates, architecture alignment,
closed source-of-truth decisions, resolved or explicitly managed blocking assumptions, a validated Livewire
session-cookie strategy, and reusable test fixtures (Playbook §5; PRD §23-P0).

**P0 must not implement NewsCMS domain features** — no articles, categories, tags, authors, media pipeline,
editor, public themes, search drivers, or other product behavior.

**Behavior = PRD. Implementation constraints = TRD. Structure = ARCHITECTURE. Order/tasks/gates = Master Playbook.**
If any conflict appears, record it and fix the source document or an ADR (Playbook §1) — never silently choose.

### P0-T04 — Source-of-truth decisions (media, permissions, audit, settings)
- **Objective/status:** Close the four ARCH §6.1 conflicts as ADRs **before** P1-T01/T03/T04 and **all** P2
  migrations. Status: Planned; **critical path**. Playbook `D-CONF-1…4` map to the four items below.
- **Owner direction (D-P0-1):** Spatie packages own their tables; NewsCMS keeps only metadata/indexes.
- **References:** ARCH §6.1; PRD §3.1.3, §16, §20; TRD §2, §6.
- **Entry/dependencies:** After P0-T03. Blocks P1-T01/P1-T03/P1-T04 and all P2 migrations. Uses Q1 input (P0-T05)
  for the body-format note only (Q1 does not block the four store ADRs).
- **Inspection steps:** ARCH §6.1, PRD §3.1.3/§16/§20, TRD §2/§6 — done in planning. Confirm no Spatie package
  installed yet (`composer show --direct`) before execution.
- **Implementation steps (ADRs + aligned spec edits in the same change, MADR format):**
  1. **ADR-0001 Media** — Spatie Media Library is authoritative for media **records and conversions**.
     PRD §20's `media`/`media_conversions` custom tables are superseded by package tables; NewsCMS keeps only
     a `media_usages` index. **No duplicate `*_media_id` FK columns** (PRD §3.1.3, §20 media rule).
     **Folder requirement preserved:** PRD §7.1 mandates nested folders, folder-scoped search/filter, and the
     storage usage meter. Media Library provides no hierarchical folders, so folder functionality is **not**
     eliminated — the ADR must explicitly decide folder ownership: NewsCMS-owned `media_folders` table
     (per PRD §20) with the media↔folder link expressed **without touching package-owned columns**
     (e.g. library custom properties or a NewsCMS-owned link table), plus how folder-scoped queries and the
     usage meter read from the combined stores. See open sub-question U1.
  2. **ADR-0002 Permissions** — `spatie/laravel-permission` owns role/permission records; PRD §20
     `roles`/`permissions`/`role_permission` superseded; permission keys remain code-owned and versioned;
     seeding never overwrites administrator-configured role assignments (TRD §6.5, ARCH §6.1).
  3. **ADR-0003 Audit** — `spatie/laravel-activitylog` is the authoritative store (+ optional custom read model);
     supersedes PRD §20 `audit_logs`; retention `AUDIT_RETENTION_DAYS` via prune job (PRD §16, TRD §6.8).
  4. **ADR-0004 Settings** — `spatie/laravel-settings` with typed settings classes is the single store;
     supersedes PRD §20 `settings`; defines language-scoped keys, validation, and cache invalidation
     (PRD §15.6, ARCH §6.1). **Package installation itself happens in P1/P2 with `dependency-review` approval —
     P0 records the decisions only.**
- **Files likely to change:** `docs/adr/0001-…0004-*.md`, `docs/PRD.md` (§20, §3.1.3), `docs/TRD.md` (§2),
  `docs/ARCHITECTURE.md` (§6.1 marked resolved), this plan.
- **Deliverables/evidence:** Four merged ADRs; PRD/TRD aligned; ARCH §6.1 closed.
- **Acceptance (verifiable):** ADR files exist and are referenced from ARCH §6.1; no PRD §20 table contradicts
  its ADR; no duplicate-ownership statement remains; PRD §7.1 folder requirements trace to ADR-0001.
- **Focused tests/broader verification:** Doc-consistency review; no code tests (no schema yet).
- **Risks:** Playbook R1 — decisions slipping into migrations; duplicate ownership. Requires human sign-off
  on U1 (folders) and on each ADR.
- **Rollback:** ADRs are reversible doc changes; if a later migration depends on one, supersede with a new ADR
  rather than editing history.
- **Blocking questions:** U1 folder-link mechanism (NewsCMS-owned link table vs library custom properties).
- **DoD/commit boundary:** One commit per ADR or single `docs(p0): source-of-truth ADRs`; each merged before
  dependent P1/P2 work.

## 11. Confirmed design direction — `design.md` scope (D-P0-5)

`docs/design.md` v1.0 Draft now exists (created under separate authorization) and is the authority for
visual/interaction decisions. The section below records the confirmed decisions and the scope + acceptance
criteria it was authored against. Coverage note: `docs/design.md` §§A–M address all 10 required sections in
§11.3. It is **not** a P0 exit-gate item and imposes no new hard dependency on P0-T01…T07.

### 11.1 Confirmed visual direction

- **Bauhaus UI:** geometric visual language, strong alignment, deliberate color usage, clear hierarchy,
  functional design.
- **Bento Grid:** modular, responsive content layouts for dashboards, news homepages, editorial sections,
  and content discovery — used where it fits; **not every screen must use a bento grid**.
- **Quiet UI:** restrained surfaces, subtle borders, purposeful whitespace, unobtrusive interactions,
  minimal visual noise.

### 11.2 Confirmed typography roles

- **Plus Jakarta Sans** (Tokotype) — primary interface and reading typeface; weights **400, 500, 600, 700**.
- **Space Mono** (Colophon Foundry) — selective use for metadata, timestamps, category labels, metrics, IDs,
  and editorial accents. **Not** the default long-form reading font.
- **As built (`docs/design.md` §C):** Plus Jakarta Sans and Space Mono are SIL OFL 1.1 (upstream license texts
  + catalog subset metadata; no font binaries vendored in repo). Jakarta: variable wght 200–800, subsets
  latin/latin-ext/vietnamese/cyrillic-ext. Space Mono: static 400/700 + italics, subsets latin/latin-ext/
  vietnamese. **Neither covers Devanagari** — the spec sets Noto Sans Devanagari (OFL-1.1, verified upstream)
  as the companion with explicit stacks (§C.2) to honor PRD §8.4 Indic-ready typography.

### 11.3 Required `design.md` sections (planned scope)

1. Design principles and the relationship between Bauhaus UI, Bento Grid, and Quiet UI.
2. Typography roles, weights, hierarchy, and line-height guidance.
3. Color tokens and semantic color roles.
4. Spacing, grid, breakpoints, borders, radii, and elevation.
5. Admin interface conventions and reusable component patterns.
6. Public news-theme conventions, including article readability and responsive content grids.
7. Interaction states, keyboard accessibility, focus visibility, and reduced-motion behavior.
8. Image handling, media ratios, and editorial card variants.
9. Font loading, licensing verification, and performance requirements.
10. Implementation guidance respecting the Laravel + Livewire + Tailwind CSS + Flux stack
    (verified §3: Laravel 13, Livewire 4.4.7, Tailwind 4.3.3 via `vite-plus`, Flux 2.20.1).
